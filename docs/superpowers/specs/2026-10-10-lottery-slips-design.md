# Design Spec: หน้าโพยหวย — กำลังดำเนินการ / ประวัติ + ตัวกรอง

- **Date:** 2026-10-10
- **Status:** Draft — รอตัดสินใจ §9 ก่อนเริ่มทำ
- **Scope:** `/lottery/slips` (รายการ) · `/lottery/slips/[slipId]` (รายละเอียด) · `GET /api/lottery/slips` · mock store · i18n 9 ภาษา

---

## 1. ของที่มีอยู่แล้ว (ตรวจจากโค้ดจริง)

| ส่วน | ตอนนี้ |
|------|--------|
| รายการโพย | `app/[lang]/lottery/slips/page.tsx` — รายการเรียงเดียว ทุกโพยแสดงสถานะ "ส่งแล้ว" เหมือนกัน ไม่มีแท็บ ไม่มีตัวกรอง |
| รายละเอียด | `/lottery/slips/[slipId]` + `LotterySlipSummary` (สรุปหลังส่งแทง · แทงต่อ) |
| ข้อมูล | `LotterySubmittedSlip` มี `status: submitted \| won \| lost \| void`, `winLoss`, `drawAt`, `purchasedAt` แต่ **ไม่มีเวลาสรุปผล** |
| API | `GET /api/lottery/slips` คืน "30 โพยล่าสุด" (จำกัดตามจำนวน ไม่ใช่ตามวัน) จาก `mockSlipStore` (ในหน่วยความจำ) |
| สิทธิ์ | `/lottery/slips` อยู่ใน `PROTECTED_PREFIXES` แล้ว (ต้อง login) |

ยังไม่มีอะไรเปลี่ยนสถานะ `submitted` → `won/lost` เลย (ใน mock)

## 2. นิยาม

- **กำลังดำเนินการ (pending)** = โพยที่ยังไม่สรุปผล → `status = submitted` รวมกรณี "เลยเวลาออกผลแล้วแต่ backend ยังไม่สรุป" (แสดงป้าย "รอสรุปผล")
- **ประวัติ (history)** = สรุปผลแล้ว → `won | lost | void`
- **ประวัติเก็บสูงสุด 30 วัน** นับจาก `settledAt` (เวลาสรุปผล) — โพย pending ไม่ถูกตัดตามวัน (อยู่จนกว่าจะสรุปผล)

## 3. โครงหน้า (Mobile-first)

```
[← โพยหวย]
[ กำลังดำเนินการ (3) | ประวัติ ]        ← CosmicLineTabs · ?tab=pending|history
[ ตลาด: ทั้งหมด ▾ ] [ ผล: ทั้งหมด ▾ ]    ← history เท่านั้นมี "ผล"
[ วันนี้ | 7 วัน | 30 วัน | กำหนดเอง ]    ← history เท่านั้น
───────────────
สรุป: {n} โพย · เดิมพันรวม ฿… (· ได้/เสียสุทธิ ฿… ในแท็บประวัติ)
┌ การ์ดโพย ───────────────┐
│ [ธง] หวยรัฐบาลไทย   [รอผล] │
│ งวด 16 ต.ค. 2569 · 4 รายการ │
│ เดิมพัน ฿200   (ได้ +฿1,800)│
│ ซื้อเมื่อ …                │
└──────────────────────────┘
[ โหลดเพิ่ม ]
```

- **แท็บกำลังดำเนินการ:** เรียงตามเวลาออกผลใกล้สุดก่อน · แสดงเวลาออกผล + ป้าย (รอออกผล / รอสรุปผล) · ตัวกรองมีแค่ "ตลาด"
- **แท็บประวัติ:** เรียงตาม `settledAt` ล่าสุดก่อน · ป้ายผล (ถูกรางวัล / ไม่ถูก / ยกเลิก) · ยอดได้/เสียใช้สี semantic (`valueClass` ตาม spec 2026-10-08: ได้ = success, เสีย = danger, ยกเลิก = neutral)
- **การ์ด** กดไปหน้ารายละเอียดเดิม · ใช้ `glass-card--soft` เดิม ไม่เพิ่ม pattern ใหม่
- ข้อความท้ายแท็บประวัติ: "เก็บประวัติย้อนหลัง 30 วัน"
- ใช้ `useUrlTab` ที่ทำไว้แล้ว (สลับแท็บทันที ไม่รอ navigation) และอุ่นข้อมูลแท็บอีกฝั่งด้วย `usePrefetchApi`

## 4. ตัวกรอง

| ตัวกรอง | ใช้กับ | ค่า | หมายเหตุ |
|---------|-------|-----|----------|
| ตลาด | ทั้งสองแท็บ | ทั้งหมด · หวยรัฐบาล · ยี่กี 5/15/30 · หวยรายวัน (รายตลาด) | รายการมาจากตลาดที่ผู้ใช้มีโพยจริง (จาก `summary`) |
| ผล | ประวัติ | ทั้งหมด · ถูกรางวัล · ไม่ถูก · ยกเลิก | |
| ช่วงเวลา | ประวัติ | วันนี้ · 7 วัน · 30 วัน · กำหนดเอง | กำหนดเอง = ใช้ `TransactionDateRangeDialog` เดิม จำกัดย้อนหลังไม่เกิน 30 วัน (วันที่เก่ากว่าเลือกไม่ได้) |
| ค้นหา | — | ไม่ทำเฟสแรก | ถ้าต้องการ: ค้นด้วย `shortId`/reference |

- ค่าตัวกรองอยู่ใน URL (`?tab=history&market=thai-government&result=won&range=7d`) → แชร์/ย้อนกลับ/รีเฟรชได้ · ค่า default ไม่ใส่ใน URL
- เปลี่ยนตัวกรองแล้ว reset หน้าเป็นหน้าแรก (cursor ใหม่)

## 5. ข้อมูลและ API

### เพิ่มใน `LotterySubmittedSlip`
```ts
settledAt: string | null;        // ISO — null = ยังไม่สรุปผล
lines[].won?: boolean;           // ผลรายบรรทัด (เฉพาะสรุปผลแล้ว)
lines[].payout?: number;         // เงินรางวัลของบรรทัด
```

### `GET /api/lottery/slips`
```
?scope=pending|history
&market=<slug>        (ไม่ใส่ = ทั้งหมด)
&result=won|lost|void (history เท่านั้น)
&from=<ISO>&to=<ISO>  (history เท่านั้น · server บังคับ from >= now-30d)
&cursor=<opaque>&limit=20
→ { slips, nextCursor, summary: { count, totalStake, totalWinLoss|null, markets: string[] } }
```
- **Retention บังคับที่ server** (`from` ถูกตัดเป็น now-30d เสมอ · mock store ลบโพย settled ที่เก่ากว่า 30 วันตอนอ่าน) — UI จำกัดวันที่เป็นแค่ความสะดวก ไม่ใช่กลไกจริง
- แบ่งหน้าแบบ cursor (20 รายการ/หน้า + ปุ่ม "โหลดเพิ่ม") — เร็วกว่าโหลดทั้งหมด และไม่ชนขีดจำกัดเดิม "30 โพย"
- `summary` ตามตัวกรองปัจจุบัน (ไม่ใช่เฉพาะหน้าที่โหลด)
- client: `useLotterySlips(scope, filters)` ใน `app/hooks/api/lottery.ts` ด้วย `useApi` (key มี scope + filters) · ใช้ `useSWRInfinite` หรือเก็บ cursor ในหน้า (เลือกตอนทำ)

### Mock สำหรับสาธิต
`submitted` → settled ต้องมีตัวทำให้เกิดเอง: ตอนอ่าน ถ้า `now > drawAt + ช่วงสรุปผล` ให้ mock สรุปผลแบบ deterministic จาก hash ของ `id` (ถูก/ไม่ถูก) แล้วเก็บ `settledAt` — backend จริงเป็นคนสรุปผล หน้าไม่ต้องเปลี่ยน

## 6. ฟังก์ชัน pure (มี test)

`lib/lottery/slipFilters.ts`:
- `partitionSlips(slips, now)` → pending / history
- `applySlipFilters(slips, filters)` — ตลาด · ผล · ช่วงเวลา
- `clampHistoryRange({from,to}, now)` — บังคับไม่เกิน 30 วัน (เขต Asia/Bangkok)
- `sortPending` (ออกผลใกล้สุดก่อน) · `sortHistory` (settledAt ล่าสุดก่อน)
- `summarizeSlips(slips)` — จำนวน · เดิมพันรวม · ได้/เสียสุทธิ
- เทสต์ขอบเขต: ครบ 30 วันพอดี · ข้ามเที่ยงคืนเวลาไทย · void ไม่นับเป็นเสีย · โพยเลยเวลาออกผลแต่ยังไม่สรุป = pending

## 7. i18n และ UI

- namespace `lottery` เพิ่มกลุ่ม `slips.*`: แท็บ · ตัวกรอง · ป้ายสถานะ (`waitingDraw`, `waitingSettle`, `won`, `lost`, `void`) · สรุป · หมายเหตุ 30 วัน · empty ต่อแท็บ · โหลดเพิ่ม
- ธงตลาดใช้ `LotteryMarketIcon` ที่มีอยู่ · วันเวลาใช้ `useLotteryI18n().dateTime` (พ.ศ. เฉพาะ th)
- ตัวเลขเงิน `formatBaht` · tabular-nums · ยอดได้/เสียใช้ `valueClass`
- ผ่าน `ui-qa-checklist` ที่ 360px · `my`/`km` ข้อความยาว (การ์ดต้อง wrap ไม่ตัดตัวเลข)

## 9. ต้องตัดสินใจก่อนเริ่ม

1. **ยกเลิก (`void`) อยู่ในประวัติใช่ไหม** (แนะนำ: ใช่ พร้อมตัวกรอง "ยกเลิก")
2. **30 วันนับจากอะไร** — แนะนำจาก `settledAt` (โพยที่ซื้อ 29 วันก่อนแต่เพิ่งออกผลวันนี้ยังอยู่ครบ 30 วันหลังออกผล) หรือจะนับจากวันซื้อ?
3. **ตลาดที่ปิดรับแล้วแต่ยังไม่ออกผล** — แสดงใน "กำลังดำเนินการ" ป้าย "รอผล" (แนะนำ) หรือแยกหมวด
4. **ต้องการยอดรวม/กำไรขาดทุนสุทธิ** ในแท็บประวัติไหม (spec นี้ใส่ไว้ — ตัดออกได้)
5. **ทางเข้าหน้านี้** — ตอนนี้มีแค่ลิงก์ footer กับหลังส่งแทง จะเพิ่มปุ่ม/เมนู "โพยของฉัน" ในหน้าหวยหรือเมนูหลักด้วยไหม
